    2 · ВЕРШИНА

    struct Vertex

    struct Vertex {
  int Data;
  Vertex *Left;
  Vertex *Right;
};

    Data — ключ. Для букв там лежит код символа ('O' = 79), поэтому буквы и числа сравниваются одинаково, обычным < и >. Left указывает на поддерево с меньшими ключами, Right — с большими. NULL означает «сына нет».

    3 · ДВОЙНАЯ КОСВЕННОСТЬ

    AddSDP и указатель на указатель

    void AddSDP(int D, Vertex **Root) {
  Vertex **p = Root;
  while (*p != NULL) {
    if (D < (*p)->Data)
      p = &((*p)->Left);
    else if (D > (*p)->Data)
      p = &((*p)->Right);
    else
      break;
  }
  if (*p == NULL) {
    *p = (Vertex *)malloc(sizeof(Vertex));
    (*p)->Data = D;
    (*p)->Left = NULL;
    (*p)->Right = NULL;
  }
}

    Главная идея, на которой держится и удаление: p имеет тип Vertex **. Он хранит не вершину, а адрес поля-указателя: либо адрес переменной Root, либо адрес поля Left/Right какой-то вершины.

    • *p — сам указатель, на который мы смотрим (то есть текущая вершина или NULL).
    • (*p)->Data — ключ текущей вершины.
    • p = &((*p)->Left) — «перевести прицел» на левое поле текущей вершины.
    • *p = ... — записать новое значение прямо в то поле родителя (или в Root), где мы остановились.

    Поэтому не нужно отдельно хранить родителя и помнить, левым или правым сыном была вершина: запись через *p сразу попадает куда нужно. Если ключ уже есть, срабатывает break, *p не равен NULL, и вершина не добавляется — повторов в дереве нет.

    Поиск такой же, как в AddSDP: идём вправо, если ключ вершины меньше X, и влево, если больше. Цикл заканчивается в двух случаях:

    • нашли вершину — break, и *p указывает на неё;
    • дошли до пустого места — *p == NULL, ключа в дереве нет, функция возвращает 0.

    Важно, что после цикла p — это адрес того поля родителя, в котором лежит найденная вершина. Именно туда потом будет записана замена.

    5 · ЗАДАНИЕ 2

    DeleteSDP: три случая

    Сначала найденную вершину запоминаем: q = *p. Дальше смотрим, сколько у неё поддеревьев.

    Нет левого поддерева

    *p = q->Right; Родитель начинает указывать на правого сына q. Если q — лист, туда запишется NULL.

    Нет правого поддерева

    *p = q->Left; То же самое, только поднимается левое поддерево.

    Два поддерева

    На место q ставим наибольшую вершину левого поддерева — самую правую. У неё нет правого сына, поэтому её легко вынуть.

    r = q->Left;              // начинаем с корня левого поддерева
s = q;                    // s — всегда родитель r
while (r->Right != NULL) { // спускаемся вправо до упора
  s = r;
  r = r->Right;
}
if (s != q) {
  s->Right = r->Left;     // 1) вынимаем r: его левые потомки остаются у s
  r->Left = q->Left;      // 2) r забирает левое поддерево q
}
r->Right = q->Right;      // 3) r забирает правое поддерево q
*p = r;                   // 4) родитель q теперь указывает на r
free(q);

    Почему именно самая правая вершина левого поддерева: она больше всех остальных ключей слева и меньше всех ключей справа. Встав на место q, она не нарушает правило «слева меньше, справа больше», и обход слева направо остаётся отсортированным.

    Шаг 1) нужен, потому что у r может быть левое поддерево. Его нельзя потерять, поэтому оно переходит на освободившееся правое место у s. Все эти ключи больше s, так что порядок сохраняется.

    7 · ЗАЧЕМ ПРОВЕРКА s != q

    Случай, когда цикл не сделал ни шага

    Если у левого сына q нет правого сына, цикл while не выполняется, и остаётся r = q->Left, s = q. Возьмём дерево из ФИО и удалим B: у неё левый сын A, правый E, и у A нет правого сына.

    Если выполнить псевдокод дословно:

    1. s->Right = r->Left → B->Right = NULL (портится сама q, это ещё не страшно, она всё равно удаляется);
    2. r->Left = q->Left → A->Left = A: вершина указывает сама на себя;
    3. r->Right = q->Right → A->Right = NULL, потому что на шаге 1 правое поле B уже затёрто. Поддерево E потеряно.

    В итоге обход дерева уходит в бесконечную рекурсию по петле A → A.

    При s == q вершина r и так стоит прямо под q со своим левым поддеревом, поэтому шаги 1) и 2) не нужны: достаточно 3) и 4). Попробуйте в визуализаторе пример «два поддерева, s = q».

    Obhod и ObhodBukvy

    void Obhod(Vertex *p) {
  if (p != NULL) {
    Obhod(p->Left);
    printf("%d ", p->Data);
    Obhod(p->Right);
  }
}

    Рекурсивный обход слева направо: сначала всё левое поддерево, потом сама вершина, потом правое. В дереве поиска это даёт ключи по возрастанию. Поэтому после каждого удаления обход — удобная проверка: последовательность должна остаться отсортированной, и в ней не должно быть только удалённого ключа. ObhodBukvy такая же, только печатает %c.

    10 · ТРУДОЁМКОСТЬ

    Сколько это стоит

    И поиск, и спуск к самой правой вершине идут по одному пути от корня вниз, а перестановка указателей — это не больше четырёх присваиваний. Значит, трудоёмкость удаления пропорциональна высоте дерева, как и при добавлении: в среднем для случайного дерева это O(log n), в худшем случае (дерево выродилось в список) — O(n).
