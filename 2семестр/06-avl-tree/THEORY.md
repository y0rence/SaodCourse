# АВЛ-дерево: теория и разбор кода

Материал вынесен из основного README. Задания и инструкции по сборке — в [README.md](README.md).

## Теория

### Двоичное дерево. Вершина

Каждая вершина хранит данные и два указателя — на левое и правое поддерево.
Для АВЛ-дерева добавляется показатель баланса:

```cpp
struct Vertex {
    int Data;        // данные (ключ)
    int Balance;     // показатель баланса
    Vertex *Left;    // левое поддерево
    Vertex *Right;   // правое поддерево
};
```

`NULL` (в псевдокоде `NIL`) — пустое поддерево. Вершина без поддеревьев —
**лист**. Самая верхняя вершина — **корень**.

### Обходы дерева (п. 9.2)

1. Сверху вниз: корень, левое поддерево, правое поддерево.
2. **Слева направо: левое поддерево, корень, правое поддерево.**
3. Снизу вверх: левое поддерево, правое поддерево, корень.

```
Обход слева направо (p: pVertex)
    IF (p ≠ NIL)
        Обход слева направо (p→Left)
        Печать (p→Data)
        Обход слева направо (p→Right)
    FI
```

Для дерева поиска обход слева направо печатает ключи **по возрастанию** —
так удобно проверять, что дерево построено правильно.

### Характеристики дерева (п. 9.3)

**Размер** — количество вершин:
```
Размер(p) = 0, если p = NIL
Размер(p) = 1 + Размер(p→Left) + Размер(p→Right)
```

**Высота** — количество уровней:
```
Высота(p) = 0, если p = NIL
Высота(p) = 1 + max(Высота(p→Left), Высота(p→Right))
```

**Средняя высота.** Сначала считается СДП — сумма длин путей от корня до
каждой вершины (L — уровень вершины, у корня L = 1):
```
СДП(p, L) = 0, если p = NIL
СДП(p, L) = L + СДП(p→Left, L+1) + СДП(p→Right, L+1)

hср = СДП(Root, 1) / Размер(Root)
```
Средняя высота показывает, сколько в среднем сравнений нужно для поиска вершины.

**Контрольная сумма** — сумма всех данных:
```
Сумма(p) = 0, если p = NIL
Сумма(p) = p→Data + Сумма(p→Left) + Сумма(p→Right)
```
Если два дерева построены из одних и тех же чисел, контрольные суммы должны
совпасть (проверка, что ни одна вершина не потерялась).

### Дерево поиска (п. 10.1)

Двоичное дерево называется **деревом поиска**, если ключ в каждой вершине
больше любого ключа в левом поддереве и меньше любого ключа в правом
поддереве. Одинаковых ключей нет. Максимальное число сравнений при поиске
`Cmax = 2h`, где h — высота дерева.

### Идеально сбалансированное дерево поиска — ИСДП (п. 10.2)

Дерево **идеально сбалансировано**, если для каждой вершины **размеры**
левого и правого поддеревьев отличаются не более чем на 1.

Свойства:
1. Высота ИСДП минимальна: `h = log2(n+1)` (округление вверх).
2. Все поддеревья ИСДП тоже идеально сбалансированы.

Построение из массива A в два этапа:
1. Отсортировать массив.
2. Корень — средний элемент; из меньших строим левое поддерево, из больших —
   правое, и так далее рекурсивно.

```
ИСДП (L, R)
    IF (L > R) ИСДП := NIL
    ELSE m := [(L+R) / 2]
         <выделяем память для p>
         p→Data := A[m]
         p→Left := ИСДП(L, m-1)
         p→Right := ИСДП(m+1, R)
         ИСДП := p
    FI
```

ИСДП даёт минимальное среднее время поиска, но его недостаток: при добавлении
нового элемента дерево приходится **строить заново**.

### АВЛ-дерево (п. 12.1)

Предложено Г. М. **А**дельсон-**В**ельским и Е. М. **Л**андисом (1962).

Дерево поиска называется **сбалансированным по высоте** (АВЛ-деревом), если
для каждой его вершины **высоты** левого и правого поддеревьев отличаются
не более чем на 1.

- Любое ИСДП является АВЛ-деревом, обратное неверно.
- Теорема Адельсона-Вельского и Ландиса: АВЛ-дерево никогда не будет выше
  ИСДП более чем на 45 %:
  `log(n+1) ≤ h_АВЛ(n) < 1,44·log(n+2) − 0,328`.
- Лучший случай — ИСДП, худший — «плохое» АВЛ-дерево (минимум вершин при
  данной высоте). Такие деревья называются **деревьями Фибоначчи**:
  `Th = <Th-1, x, Th-2>`, число вершин `n0 = 0, n1 = 1, nh = nh-1 + 1 + nh-2`.

### Показатель баланса (п. 12.2)

```
Balance = -1   левое поддерево на 1 выше правого
Balance =  0   высоты поддеревьев равны
Balance = +1   правое поддерево на 1 выше левого
```

Пусть новая вершина добавлена в левое поддерево вершины и его высота выросла
на 1. Возможны три случая:
1. `hL = hR` — высоты станут разными, но баланс не нарушен (Balance станет −1);
2. `hL < hR` — высоты сравняются, баланс улучшится (Balance станет 0);
3. `hL > hR` — баланс нарушен (стал бы −2), дерево надо перестроить **поворотом**.

### Повороты (п. 12.2)

Обозначения: `p` — вершина, где нарушился баланс; T1…T4 — поддеревья.

#### LL-поворот
Перекос влево, и у левого сына тоже перекос влево (добавили в левое
поддерево левого сына).

```
          p→ B                       A
            / \                     / \
       q→  A   T3      LL         T1   B
          / \          =>             / \
        T1   T2                     T2   T3
```
```
q := p→Left
q→Balance := 0
p→Balance := 0
p→Left := q→Right
q→Right := p
p := q
```

#### RR-поворот
Зеркальный LL: перекос вправо, у правого сына тоже вправо.

```
        p→ A                         B
          / \                       / \
        T1   B  ←q     RR          A   T3
            / \        =>         / \
          T2   T3               T1   T2
```
```
q := p→Right
q→Balance := 0
p→Balance := 0
p→Right := q→Left
q→Left := p
p := q
```

#### LR-поворот (двойной)
Перекос влево, но у левого сына перекос вправо (добавили в правое поддерево
левого сына). Наверх поднимается внук `r`.

```
          p→ C                          B
            / \                       /   \
      q→   A   T4       LR           A     C
          / \           =>          / \   / \
        T1   B ←r                 T1  T2 T3  T4
            / \
          T2   T3
```
```
q := p→Left, r := q→Right
IF (r→Balance < 0) p→Balance := +1 ELSE p→Balance := 0 FI
IF (r→Balance > 0) q→Balance := -1 ELSE q→Balance := 0 FI
r→Balance := 0
p→Left := r→Right, q→Right := r→Left
r→Left := q, r→Right := p, p := r
```

#### RL-поворот (двойной)
Зеркальный LR.

```
        p→ A                            B
          / \                         /   \
        T1   C  ←q      RL           A     C
            / \         =>          / \   / \
      r→   B   T4                 T1  T2 T3  T4
          / \
        T2   T3
```
```
q := p→Right, r := q→Left
IF (r→Balance > 0) p→Balance := -1 ELSE p→Balance := 0 FI
IF (r→Balance < 0) q→Balance := 1 ELSE q→Balance := 0 FI
r→Balance := 0
p→Right := r→Left, q→Left := r→Right
r→Left := p, r→Right := q, p := r
```

**Как выбрать поворот:**

| Где нарушен баланс | Баланс сына | Поворот |
|---|---|---|
| слева (Balance был −1, выросла левая ветвь) | левый сын `< 0` | LL |
| слева | левый сын `> 0` | LR |
| справа (Balance был +1, выросла правая ветвь) | правый сын `> 0` | RR |
| справа | правый сын `< 0` | RL |

### Добавление вершины в АВЛ-дерево (п. 12.3)

1. Вершина добавляется как в обычное дерево поиска (спуск по пути поиска до
   пустого места).
2. Затем, **возвращаясь назад по пути поиска** (это делает рекурсия),
   пересчитываем баланс и ищем вершину, где он нарушился. Если такая
   есть — делаем поворот.

Логическая переменная **Рост** показывает, выросла ли высота поддерева.
После поворота высота поддерева становится такой же, как была до добавления,
поэтому `Рост := ЛОЖЬ` и выше по пути ничего менять уже не надо.

```
Добавление в АВЛ-дерево (D: данные; Var p: pVertex)
IF (p = NIL)
    new(p), p→Data := D, p→Left := NIL, p→Right := NIL
    p→Balance := 0, Рост := ИСТИНА
ELSE
    IF (p→Data > D)
        Добавление в АВЛ-дерево (D, p→Left)
        IF (Рост = ИСТИНА)                 {выросла левая ветвь}
            IF (p→Balance > 0) p→Balance := 0, Рост := ЛОЖЬ
            ELSE IF (p→Balance = 0) p→Balance := -1
            ELSE
                IF (p→Left→Balance < 0) <LL-поворот>
                ELSE <LR-поворот>
                FI
                Рост := ЛОЖЬ
            FI
        FI
    ELSE IF (p→Data < D)
        <аналогичные действия для правого поддерева>
    ELSE {p→Data = D, такая вершина уже есть}
    FI
FI
```

Программа проверена на примере из пособия (рис. 45:
`B 9 2 4 1 7 E F A D C 3 5 8 6`) — получается такое же дерево с корнем `B`.

## Разбор кода: как двигаются указатели

### Почему `Vertex *&p`

В псевдокоде функция получает `Var p: pVertex` — указатель передаётся
**по ссылке**, чтобы функция могла **изменить сам указатель** у родителя
(записать туда новую вершину или новый корень после поворота).

В C++ это пишется `Vertex *&p` («ссылка на указатель»). Когда мы вызываем
`AddAVL(D, p->Left)`, внутри функции `p` — это не копия, а **то самое поле
`Left` родителя**. Поэтому:

- `p = new Vertex;` — новая вершина сразу «подвешивается» к родителю;
- в повороте `p = q;` — у родителя (или у переменной корня в `main`)
  вместо старой вершины оказывается новая вершина поддерева.

Без `&` изменилась бы только локальная копия, и дерево «потеряло бы» вершины.

### Как работает добавление (шаг за шагом)

```cpp
void AddAVL(int D, Vertex *&p)
```

1. **Спуск вниз.** Если `p->Data > D`, вызываем `AddAVL(D, p->Left)`,
   если `p->Data < D` — `AddAVL(D, p->Right)`. Так указатель «двигается»
   по пути поиска, пока не упрётся в `NULL`.
2. **Создание вершины.** На месте `NULL` создаём вершину (`new`),
   Balance = 0, `Rost = true` — поддерево выросло.
3. **Подъём вверх.** Рекурсивные вызовы завершаются по очереди, и мы
   возвращаемся к каждой вершине на пути поиска — от нового листа к корню.
   В каждой проверяем `Rost`:
   - если `Rost == false` — ничего не делаем (выше ничего не изменилось);
   - если выросла левая ветвь:
     - Balance был `+1` → стал `0`, `Rost = false` (дерево выровнялось);
     - Balance был `0` → стал `−1`, `Rost` остаётся `true` (поднимаемся дальше);
     - Balance был `−1` → стал бы `−2` → поворот `LL` или `LR`, `Rost = false`.
   - для правой ветви всё зеркально.
4. Если такой ключ уже есть — ничего не добавляем, `Rost = false`.

`Rost` — глобальная переменная, как в пособии: её выставляет вложенный вызов,
а читает вызов уровнем выше.

### Как двигаются указатели в LL-повороте

```cpp
Vertex *q = p->Left;   // q - левый сын (A), p - вершина с нарушением (B)
q->Balance = 0;
p->Balance = 0;
p->Left = q->Right;    // T2 переезжает: был правым у A, стал левым у B
q->Right = p;          // B становится правым сыном A
p = q;                 // родитель теперь указывает на A (новый корень поддерева)
```

RR — то же самое зеркально (`Left` ↔ `Right`).

### Как двигаются указатели в LR-повороте

```cpp
Vertex *q = p->Left;   // q = A
Vertex *r = q->Right;  // r = B (внук, он поднимется наверх)
// новые балансы считаем по старому балансу r
p->Left = r->Right;    // T3 (правое у B) -> левое у C
q->Right = r->Left;    // T2 (левое у B)  -> правое у A
r->Left = q;           // A - левый сын B
r->Right = p;          // C - правый сын B
p = r;                 // родитель указывает на B
```

RL — то же самое зеркально.

### ИСДП

Массив `A[1..N]` сортируется (`SelectSort` — прямой выбор), затем
`ISDP(1, N)` берёт средний элемент `m = (L+R)/2` в корень и рекурсивно строит
левое поддерево из `A[L..m-1]` и правое из `A[m+1..R]`.
Индексы с 1, как в пособии.

### Случайные числа

`FillRand` заполняет `A[1..100]` случайными числами от 0 до 999 **без
повторов** (в дереве поиска одинаковых ключей быть не должно, иначе
размер АВЛ-дерева был бы меньше 100). `srand(time(NULL))` — чтобы при
каждом запуске числа были разные.

### Средняя высота

`(double)SDP(p, 1) / Size(p)` — приведение к `double`, чтобы деление было
не целочисленным.
