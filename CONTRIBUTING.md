# Как вносить изменения

Правила работы с репозиторием лабораторных работ, страниц лаб и курсовой.

## Ветки

Каждая задача — отдельная ветка от `main`:

```bash
git switch main && git pull
git switch -c fix/короткое-описание    # баги: fix/…
git switch -c feat/короткое-описание   # новые страницы, генераторы: feat/…
git switch -c docs/короткое-описание   # README, документация: docs/…
git switch -c ci/короткое-описание     # workflow и проверки: ci/…
```

Название ветки — латиницей, в нижнем регистре, через дефис.

## Pull request

1. Откройте PR даже для небольших улучшений — так изменения проходят ревью и не копятся.
2. В описании: **что сделано**, **зачем** (какую проблему решает), **как проверить**.
3. Слияние в `main` только через PR, merge-коммитом (`--no-ff`) — в истории остаются границы задач.
4. После слияния ветку удалить.

## Обязательные проверки

Перед отправкой PR (и автоматически в CI — `.github/workflows/checks.yml`):

```bash
node --check assets/lab.js
node --check assets/gens/*.js scripts/*.js

node scripts/check-lab.js $(find . -name lab.html | sort)
node scripts/run-steps.js $(find . -name lab.html | sort)

python3 scripts/readme-monochrome.py   # README без изменений = стиль соблюдён
```

Все 25 страниц `lab.html` должны дать `✓` в обоих скриптах: `run-steps.js`
помимо прогона шагов сверяет теги строк кода с тегами шагов — если вы
добавили шаг с новым тегом, промаркируйте строку в `pseudo` или `file.lines`.

## Стиль

- **README и страницы лаб** — строгий монохром: без эмодзи, без цветных
  shields-бейджей, статусы в таблицах — словами (`да` / `нет`).
  Формат описан в [docs/lab-pages.md](docs/lab-pages.md).
- **Код** — один `.clang-format` (LLVM, отступ 4 пробела, ширина 100),
  без комментариев в лабораторных исходниках: теория — в README/THEORY.
- **Коммиты** — на русском, начинаются с существительного или инфинитива
  области: `Страницы: …`, `README: …`, `CI: …`.

## Новые страницы лаб

1. Скопируйте конфиг соседней работы (`lab.html`) и эталон
   `1семестр/01-quadratic-sorts/01-select-sort/lab.html`.
2. Генератор шагов положите в `assets/gens/*.js`, подключив строкой **перед**
   `assets/lab.js` (см. [docs/lab-pages.md](docs/lab-pages.md)).
3. Добавьте ссылки: пилюлю «▶ Страница» в карточку `index.html`, строку
   `> **Интерактивная страница:** …` в README работы, `[страница](…)` в
   таблицу семестра.

## Чего нельзя коммитить

- бинарники, `.DS_Store`, `*.dSYM` — уже в `.gitignore`;
- персональные данные, токены, ключи;
- большие файлы без необходимости (исходники PDF кладём только в
  `Курсовая/`, если они часть задания).
